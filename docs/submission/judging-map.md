# Judging alignment — Fortified Enterprise Fleet

## Innovation and operational utility — 40%

IsoPact targets the gap between agent completion and business settlement. In the canonical $200 missing-order case, independent Support, Fulfillment, and Retention actions project $650 compensation and $450 excess exposure. IsoPact authorizes $250 and prevents $400 of projected invalid value. The authentic “unlikely hero” is the commerce operations supervisor who must answer: **Did the business actually settle correctly after every agent said it was done?**

Four agents are necessary because they represent separately deployed enterprise functions with legitimate local goals: financial remedy, delivery remedy, relationship remedy, and cross-system recovery. The contradiction exists at the combined business-outcome level, not inside one agent prompt.

Evidence: Stage 8 live fleet, Stage 11 UI, Stage 12 benchmark, canonical signed receipt.

## Architectural discipline — 30%

- Gemini/ADK reasoning is separated from deterministic enforcement.
- Semantic operation identity and exclusive resolution slots define business authority.
- Firestore transaction reservation precedes external calls.
- Ambiguous transports persist as `OUTCOME_UNKNOWN`.
- Ranked, source-specific evidence state machines control corrections and settlement.
- A closed Compensation Registry, approval, and TOCTOU revalidation constrain recovery.
- Managed Agent Identity authenticates runtime actors; Memory Bank is non-authoritative; Model Armor screens model-facing input.
- Hash-chained claims and KMS receipts make tampering detectable.
- OpenTelemetry reconstructs causality without participating in authority.

Google services are used because each establishes a boundary, not to fill a logo grid. Agent Gateway is excluded from canonical traffic and A2A is not claimed.

## Demo and production readiness — 30%

The public UI demonstrates live Agent Runtime execution, Cloud Run enforcement, Firestore/Pub/Sub evidence, BLOCK decisions, Rank 1 settlement, KMS receipt verification, tamper detection, TOCTOU refusal, and reconciliation. The repository provides exact locks, SBOM, immutable digest, clean-room verification, benchmark evidence, deployment inventory, and one non-destructive release command.

Known limitations remain prominent: narrow commerce registry, no Firestore PITR/delete protection, same-pact provenance contention, small reconciliation sample, and enterprise-specific adapter work.
